# 微信小程序「审批单查看」需求文档

| 项目 | 内容 |
|---|---|
| 文档名称 | 微信小程序审批单查看功能需求说明书 |
| 版本 | V1.0（初稿） |
| 日期 | 2026-11-13 |
| 端形态 | 微信小程序（企业主体，已认证） |
| 一期范围 | 登录/绑定、待处置审批单、历史审批单 |
| 关联系统 | 现有审批后台（PC 端），本期小程序为**移动端只读查询入口** |

---

## 1. 项目概述

### 1.1 背景

现有审批流程仅在 PC 后台使用，审批人外出时无法及时知晓待办、也无法随时查阅历史审批记录。需建设一个轻量微信小程序，让员工用微信直接进入，查看「待我处置的审批单」与「我已处理的历史审批单」。

### 1.2 目标

| 目标 | 衡量方式 |
|---|---|
| 免密进入 | 已绑定用户从点击小程序到看见待办列表 ≤ 3 秒，0 次输入 |
| 首次绑定顺畅 | 新用户从授权到绑定成功 ≤ 30 秒，失败可明确知道原因 |
| 待办不漏 | 小程序角标数 = 后台待办数（误差 0） |
| 历史可查 | 支持按状态、时间、关键字检索，1 年内记录可查 |

### 1.3 用户角色

| 角色 | 说明 | 权限 |
|---|---|---|
| 审批人 | 后台已存在的系统账号，被指派审批任务 | 查看待处置、查看历史、查看详情 |
| 未绑定员工 | 有系统账号但首次使用小程序 | 仅可登录并绑定 |
| 无账号人员 | 无系统账号 | 提示联系管理员，不可自助注册 |

### 1.4 本期不做（明确排除）

- 在小程序内**执行**审批动作（同意/驳回/转交）—— 见第 12 章待确认
- 发起新审批单
- 附件预览与下载（一期仅展示附件名称与数量）
- 消息订阅推送（一期用小程序角标 + 手动下拉刷新）

## 2. 名词定义

| 名词 | 定义 |
|---|---|
| 微信一键登录 | 调用 `wx.login` 静默获取临时 code，后端换取 openid 后匹配已绑定账号，直接签发登录态；用户全程无输入 |
| 绑定 | 将微信身份（openid）与系统账号（user_id）建立 1:1 关联关系，从此可免密登录 |
| 待处置审批单 | 当前审批节点指派给「我」且任务状态为「待处理」的审批单 |
| 历史审批单 | 「我」已处理完毕的审批单（通过 / 驳回 / 退回），按处理时间倒序 |
| 登录票据 | 后端签发的短期凭证（JWT），前端存储于 Storage，用于后续接口鉴权 |

## 4. 功能需求详述

### F1 登录模块

#### F1-1 微信一键登录

**触发时机**：小程序冷启动 / 从后台切回前台且登录态已过期。

**流程**：

```
小程序启动
  → wx.login() 取 code（5 分钟有效，一次性）
  → POST /api/auth/wx/login { code }
  → 后端 auth.code2Session 换 openid / unionid
  → 查 sys_user_wx_bind
      ├─ 命中 + 账号正常      → 返回 token，直接进「待处置」首页
      ├─ 命中 + 账号已停用    → 提示「账号已停用，请联系管理员」，停留登录页
      ├─ 未命中（新微信）     → 返回 bindTicket，跳「账号密码登录页」
      └─ 命中 + 账号已删除    → 清理绑定记录，按未命中处理
```

**规则**：

1. 一键登录失败时**不得弹授权框骚扰用户**，直接跳账号密码页，并在页面顶部显示具体原因
2. `session_key` 只允许后端持有，**严禁下发到小程序端**
3. 前端不存储 openid，openid 仅在后端与 `user_id` 关联
4. 同一 openid 只允许绑定 1 个系统账号（1:1）
5. 同一系统账号只允许绑定 1 个 openid（一期限制，多设备换微信需先解绑）

#### F1-2 账号密码登录 + 自动绑定

**页面元素**：

| 元素 | 规则 |
|---|---|
| 账号输入框 | 必填，支持工号或手机号，长度 4~32，去首尾空格 |
| 密码输入框 | 必填，密文显示，支持「显示/隐藏」切换，长度 6~32 |
| 登录按钮 | 两字段均非空才可点击；点击后 loading，防重复提交 |
| 提示文案 | 「首次使用需绑定微信，绑定后下次可直接进入」 |
| 忘记密码 | 仅提示「请在 PC 端重置密码」，不做小程序内重置 |

**流程**：

```
提交账号密码
  → POST /api/auth/login { username, password(HTTPS 加密), bindTicket }
  → 校验账号密码
      ├─ 失败 → 提示「账号或密码错误」，累计错误次数 +1
      ├─ 账号停用 → 「账号已停用，请联系管理员」
      └─ 成功 → 若携带 bindTicket：写 sys_user_wx_bind（自动绑定，无需二次确认）
               → 返回 token → 进「待处置」首页
```

**规则**：

1. 密码必须 HTTPS 传输；建议前端用后端下发的 RSA 公钥加密后提交，后端解密比对
2. 连续错误 5 次锁定 15 分钟，提示剩余锁定时间；锁定状态由后端判定
3. 绑定动作在服务端与登录同事务完成，绑定失败不影响本次登录（记告警日志），下次启动仍走账号密码
4. `bindTicket` 有效期 5 分钟、一次性，防止跨会话错绑

#### F1-3 登录态维持

| 项 | 规则 |
|---|---|
| 凭证 | JWT，access token 有效期 2 小时，refresh token 7 天 |
| 存储 | `wx.setStorageSync('token')`，不存明文密码 |
| 续期 | 每次启动调 `wx.checkSession` + 后端 `/auth/refresh`；access 过期用 refresh 静默换新 |
| 失效处理 | 任一接口返回 401 → 清理本地 token → 重新走 F1-1 静默登录 |
| 切前台 | `onShow` 校验一次登录态，不刷新页面数据（避免打断阅读） |

#### F1-4 退出登录 / 换绑

1. 「我的」页提供「退出登录」：清本地 token，`wx.login` 后回到启动页（因已绑定，会再次免密进入，故退出仅用于切换账号）
2. 需真正切换账号时提供「解除微信绑定」：二次确认弹窗 → `POST /api/auth/unbind` → 清理绑定 → 跳账号密码页重新绑定
3. 解绑后原微信不再能一键登录，原账号可用密码在其他微信重新绑定

#### F1-5 异常与降级清单

| 场景 | 判定方式 | 提示文案 | 处理 |
|---|---|---|---|
| 微信 code 换取失败 | code2Session 返回 errcode | 「微信登录未成功，请使用账号密码登录」 | 降级账号密码页，展示 bindTicket 不可用则重新 wx.login |
| 网络异常 / 超时 | 请求 5s 超时 | 「网络不给力，请重试」 | 重试 1 次，仍失败停留登录页 |
| 用户微信版本过低 | 基础库 < 2.20.0 | 「请升级微信后重试」 | 阻断 |
| 未绑定 | 后端返回 `NEED_BIND` | 「该微信尚未绑定账号，请先登录」 | 跳登录绑定页 |
| 账号已停用 | 后端返回 `USER_DISABLED` | 「账号已停用，请联系管理员」 | 阻断 |
| 无系统账号 | 登录失败 | 「账号不存在，请联系管理员开通」 | 阻断，不提供注册入口 |
| 绑定冲突（该账号已绑其他微信） | 后端返回 `BIND_CONFLICT` | 「该账号已绑定其他微信，请先解绑」 | 阻断，引导联系管理员 |

### F2 待处置审批单

#### F2-1 列表

**展示字段（每条）**：

| 字段 | 说明 |
|---|---|
| 审批单号 | 如 `SP2026111300012` |
| 标题 | 审批单标题，单行省略，最多 2 行 |
| 业务类型 | 标签样式，如「采购」「请假」「费用报销」 |
| 申请人 | 姓名 + 部门简称 |
| 提交时间 | 相对时间（今天 09:30 / 昨天 / 11-05） |
| 紧急标识 | 超时未处理（>24h）显示红色「超时」角标 |
| 摘要 | 关键字段 1~3 条（金额 / 天数 / 事由），后台按类型配置 |

**交互**：

| 交互 | 规则 |
|---|---|
| 排序 | 按提交时间倒序（可切换为超时优先，一期固定倒序） |
| 分页 | 每页 20 条，触底加载；加载中显示「加载中」，无更多显示「没有更多了」 |
| 下拉刷新 | 支持，刷新后总数同步更新 |
| 空态 | 插图 + 「暂无待处置审批单」 |
| 点击 | 跳详情页，进入前把该条标记为「已读」（仅前端本地，不上报后端） |
| 角标 | 小程序 TabBar「待处置」显示未读数；未读数由后端 `/approval/badge` 聚合 |

#### F2-2 筛选与搜索

| 能力 | 规则 |
|---|---|
| 搜索 | 支持审批单号、标题、申请人姓名模糊匹配，输入 300ms 防抖 |
| 类型筛选 | 多选，默认全选；选项来自后端字典接口 |
| 时间范围 | 快捷项：近 7 天 / 近 30 天 / 自定义；默认近 30 天 |
| 重置 | 一键清空筛选条件恢复默认 |

#### F2-3 审批单详情

**信息分区**：

1. **头部**：标题、状态标签、单号（可长按复制）
2. **基础信息**：申请人、部门、提交时间、业务类型、紧急程度
3. **表单内容**：按业务类型动态渲染只读字段（键值对列表，长文本自动换行）
4. **附件**：仅列出文件名与大小，点击提示「请在 PC 端查看」
5. **审批流程**：竖向时间轴，节点顺序展示 —— 已通过（绿色）、处理中（蓝色高亮）、未开始（灰色）、已驳回（红色）；每个节点显示处理人、处理时间、处理意见
6. **底部**：一期无操作按钮，仅「返回」；预留「去 PC 处理」入口（点击复制单号）

### F3 历史审批单

#### F3-1 列表

与 F2-1 结构一致，差异字段与规则：

| 项 | 规则 |
|---|---|
| 数据范围 | 当前登录人是该单任一节点的处理人，且该单已离开该节点（同意 / 驳回 / 退回） |
| 默认排序 | 按「我的处理时间」倒序 |
| 特有字段 | 我的处理结果（通过/驳回/退回标签）、我的处理时间、当前单据状态 |
| 筛选 | 处理结果（全部/通过/驳回/退回）、业务类型、时间范围（近 7 天/30 天/自定义，最长 1 年） |
| 数据量 | 单账号可能上万条，必须服务端分页 + 索引（见 6.3） |

#### F3-2 详情

复用 F2-3 页面，差异：

- 头部状态展示**单据当前状态**（可能已归档）
- 时间轴中「我的处理节点」高亮标注「我的处理」
- 若有后续节点，仅在已产生记录时展示

## 5. 核心流程时序

### 5.1 首次使用（未绑定）

```
用户          小程序                后端                微信服务器
 |  点击进入     |                    |                    |
 |------------->|  wx.login()        |                    |
 |              |------------------->|                    |
 |              |                    |-- code2Session --->|
 |              |                    |<-- openid ---------|
 |              |                    | 查绑定表：未命中    |
 |              |<-- NEED_BIND + ticket                   |
 |  看到登录页   |                    |                    |
 |  输入账号密码 |                    |                    |
 |------------->|-- POST /auth/login ->|  校验通过          |
 |              |                    |  写绑定(事务)       |
 |              |<-- token ----------|                    |
 |  进入待办列表 |                    |                    |
```

### 5.2 后续使用（已绑定）

```
点击进入 → wx.login → /auth/wx/login → 命中绑定 → 返回 token → 待办列表
（全程 0 输入，用户无感知）
```

### 5.3 登录态过期

```
任意接口返回 401 → 清本地 token → 静默 wx.login → /auth/wx/login → 换新 token → 重放原请求 1 次
（重放仍失败 → 跳登录页，不弹重复错误提示）
```

## 6. 数据模型建议

### 6.1 新增表

```sql
-- 微信绑定表（1 微信 : 1 账号）
CREATE TABLE `sys_user_wx_bind` (
  `id`          bigint(20) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `user_id`     bigint(20) NOT NULL COMMENT '系统用户ID',
  `openid`      varchar(64) NOT NULL COMMENT '微信openid（小程序维度唯一）',
  `unionid`     varchar(64) DEFAULT NULL COMMENT '微信unionid（绑定开放平台后可用）',
  `bind_time`   datetime DEFAULT CURRENT_TIMESTAMP COMMENT '绑定时间',
  `unbind_time` datetime DEFAULT NULL COMMENT '解绑时间',
  `status`      tinyint(1) DEFAULT 1 COMMENT '状态：0-已解绑，1-已绑定',
  `last_login_time` datetime DEFAULT NULL COMMENT '最近登录时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_openid` (`openid`, `status`),
  KEY `idx_user_id` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户微信绑定表';
```

> 注：`uk_openid(openid, status)` 允许历史解绑记录共存；业务层保证 status=1 时 openid 唯一。

### 6.2 审批单相关表（若已有则复用，仅列出小程序依赖字段）

```sql
-- 审批单主表
flow_order(
  id, order_no, title, biz_type, applicant_id, dept_id,
  apply_time, status, current_node, summary_json, ext_json, deleted
)

-- 审批任务表（一个审批单多个节点）
flow_task(
  id, order_id, node_seq, node_name, assignee_id,
  status,       -- 0待处理 1已通过 2已驳回 3已退回 4已跳过
  handle_time, opinion
)

-- 审批日志表（时间轴数据源，含非任务类动作）
flow_log(
  id, order_id, task_id, action, operator_id, operate_time, opinion
)
```

### 6.3 索引要求

| 查询场景 | 必需索引 |
|---|---|
| 待办列表（assignee + status） | `flow_task(assignee_id, status, id DESC)` |
| 历史列表（assignee + status + handle_time） | `flow_task(assignee_id, status, handle_time DESC)` |
| 详情按单号 | `flow_order(uk_order_no)` |
| 详情按 ID 取节点 | `flow_task(order_id, node_seq)` |
| 绑定查询 | `sys_user_wx_bind(uk_openid)`、`idx_user_id` |

## 7. 接口清单

| # | 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|---|
| 1 | POST | `/api/auth/wx/login` | code 换登录态 / 返回 NEED_BIND | 否 |
| 2 | POST | `/api/auth/login` | 账号密码登录（可带 bindTicket 自动绑定） | 否 |
| 3 | POST | `/api/auth/unbind` | 解绑当前微信 | 是 |
| 4 | POST | `/api/auth/refresh` | 刷新 token | refresh |
| 5 | POST | `/api/auth/logout` | 退出（服务端作废 refresh） | 是 |
| 6 | GET | `/api/approval/badge` | 待办数量（用于 TabBar 角标） | 是 |
| 7 | GET | `/api/approval/pending` | 待处置列表，参数 `page,size,keyword,bizType,dateFrom,dateTo` | 是 |
| 8 | GET | `/api/approval/history` | 历史列表，参数 `page,size,result,bizType,dateFrom,dateTo` | 是 |
| 9 | GET | `/api/approval/{id}` | 详情（含时间轴、附件元数据） | 是 |
| 10 | GET | `/api/dict/biz-type` | 业务类型字典 | 是 |

**统一响应**：

```json
{ "code": 0, "msg": "ok", "data": {}, "traceId": "..." }
```

| code | 含义 | 前端行为 |
|---|---|---|
| 0 | 成功 | — |
| 401 | 登录态失效 | 静默重新登录 |
| 1001 | 需绑定（NEED_BIND） | 跳登录绑定页 |
| 1002 | 账号停用 | 阻断提示 |
| 1003 | 绑定冲突 | 阻断提示 |
| 1004 | 密码错误（含剩余锁定次数） | 表单提示 |
| 1005 | 连续错误已锁定 | 提示解锁时间 |

## 8. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 列表首屏 ≤ 1.5s（4G），分页加载 ≤ 800ms；详情 ≤ 2s |
| 兼容 | 微信 ≥ 8.0，基础库 ≥ 2.20.0；iOS / Android 主流机型；屏幕适配 320~430px 宽 |
| 安全 | 全链路 HTTPS；密码 RSA 加密提交；token 不落日志；接口按当前用户过滤数据（严禁前端传 userId） |
| 权限 | 越权校验：详情接口必须校验当前用户是该单节点处理人或申请人，否则 403 |
| 可用性 | 后端异常时列表展示重试按钮，不白屏；关键链路埋点可追溯 |
| 合规 | 隐私政策页必填（微信审核强制）；收集信息仅 openid + 登录态；不强制授权头像昵称 |
| 数据保留 | 历史审批单在线可查 1 年，超期归档（后台可查） |

## 11. 验收标准

| # | 场景 | 预期结果 |
|---|---|---|
| 1 | 已绑定用户首次点击小程序 | 3 秒内直接进入待办列表，无任何输入 |
| 2 | 新微信首次进入 | 自动跳账号密码页，顶部提示「该微信尚未绑定账号」 |
| 3 | 输入正确账号密码 | 登录成功并自动绑定，杀进程重进后免密 |
| 4 | 输入错误密码 5 次 | 第 5 次提示「已锁定，15 分钟后重试」，第 6 次即使密码正确也拒绝 |
| 5 | 停用账号登录 | 提示「账号已停用，请联系管理员」，无法进入 |
| 6 | 账号已绑其他微信 | 提示绑定冲突，不产生重复绑定记录 |
| 7 | 待办列表 | 条数与 PC 后台一致，下拉刷新后角标数同步 |
| 8 | 待办超 24 小时 | 列表显示红色「超时」标识 |
| 9 | 历史列表筛选「驳回」 | 仅返回我驳回的单据，按处理时间倒序 |
| 10 | 打开他人审批单详情（构造 ID） | 返回 403，不泄露任何字段 |
| 11 | token 过期后滑动列表 | 静默重新登录并正常加载，用户无感知 |
| 12 | 断网状态进入 | 展示网络异常提示与重试按钮，不白屏 |

## 12. 待确认事项

| # | 问题 | 当前文档假设 | 影响 |
|---|---|---|---|
| 1 | **一期是否要在小程序内做审批操作** | 假设只读；「待处置」意为「待查看处理」，操作回 PC | 若需在小程序审批，需增加 F4 模块与审批二次确认、审计留痕，工作量 +40% |
| 2 | 是否提供**手机号一键授权**登录（`getPhoneNumber`） | 不提供，改用 openid 免密 | 手机号组件需企业认证且按次计费；若已有手机号与账号映射，可作为更快绑定方式 |
| 3 | 一个账号是否允许多微信绑定（如工作/私人微信） | 假设 1:1 | 放开则 `sys_user_wx_bind` 去掉唯一约束，并需「常用设备」管理 |
| 4 | 「历史审批单」是否包含「我发起的」 | 假设仅「我处理过的」 | 若包含则需增加 Tab 与权限维度 |
| 5 | 是否需要微信订阅消息推送待办提醒 | 一期不做，仅角标 | 推送需用户逐次授权，且模板消息需审核 |
| 6 | 审批单详情中附件是否必须可看 | 一期仅列名称 | 小程序预览 PDF/图片需额外开发，敏感附件还需水印与下载管控 |
| 7 | 现有后台是否已有统一账号体系与 JWT | 假设有，小程序复用 | 若无则需先补 `/auth/login` 与用户表 |
